## 本輪新增：單例進度服務也依 UID 隔離

前一輪已完成 SaveManager 與 Life / Gold / Tool 快取隔離；本輪進一步發現 `PlayerProgressService.instance` 是全域單例，原先即使本機存檔已切換帳號，單例內仍可能暫時保留前一帳號的章節進度、解鎖章節及 active Session。

已修改：
- 新增 `PlayerProgressService.bindAccount(uid)`。
- UID 改變時，遞增 Session operation generation、使舊 refresh generation 失效、清除 pending start 引用、章節進度、解鎖章節及 active Session 狀態。
- 主畫面的 Firebase Auth 路由將 SaveManager 與 PlayerProgressService 綁定放在同一初始化流程；登出狀態也會執行解除綁定。
- 登入流程在進入 Profile/Home 前綁定 PlayerProgressService。
- 登出流程會清除 singleton progression state。
- 新增 `callable_contract.test.js` 靜態契約，確保主 Auth 路由、登入、登出及 singleton reset 連線不會被未來修改移除。

## 其他帳號隔離修正

- SaveManager：UID 專屬存檔、Session ID、玩家名稱、玩家 ID、頭像；只有伺服器 Session 完全匹配才遷移舊版全域棋盤。
- SaveManager 綁定帳號改變時清除 Life / Gold / Tool 記憶體快取。
- Life / Gold / Tool 的非同步請求檢查 UID/generation，拒絕過期結果。
- PlayerProgressService start / refresh / restart / abandon / completion 路徑在提交狀態前檢查 UID 或 operation generation。
- PlayerProfileService 的初始化、名稱、頭像更新在寫本機快取前檢查 UID。
- CreatureCollectionService 丟棄過期圖鑑讀取，帳號切換後停止後續發現操作。
- AdminService 丟棄帳號切換後的管理員角色讀取。
- PendingOperationStore 可依原始 UID 清理操作記錄。
