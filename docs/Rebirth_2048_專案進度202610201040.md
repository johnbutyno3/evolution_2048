# Rebirth 2048 專案進度 — 2026-10-20 10:40

## RESET 強制關閉恢復流程：第一版已接入

本輪直接修改主專案分支 `fix/game-state-root-cause-20261019`：

- `PendingOperationStore` 現在可將完整 pending payload 以 JSON 寫入 SharedPreferences，包含 operation ID、operation key、chapter、replay log、replay session ID、initial tiles 與替換棋盤快照。
- RESET 在呼叫後端前先保存 payload；若保存失敗，停止新棋盤並還原舊棋盤，避免在未留下恢復資料時送出扣命請求。
- 遊戲啟動時，先檢查同帳號／同章節的 pending RESET；使用原 operation ID 和原請求重試後端，再把保存的同一份棋盤快照綁定到後端回傳的 session ID，成功保存後才清除 pending 記錄。
- 若 operation ID 的獨立本機鍵遺失，會從 payload 還原；若本機鍵與 payload 衝突，恢復流程會 fail closed，不會直接建立另一局。
- 清理順序改為先刪 payload、再刪 operation key，避免 key 已清除但恢復 payload 還在時造成重試使用新 ID。
- `callable_contract.test.js` 新增契約檢查，保護 payload、operation ID 與啟動恢復流程。
