### Security Enforcement

`functions/security_enforcement.js`

目前責任：

- risk level：NORMAL / WARNING / ADMIN_ALERT / CRITICAL。
- sensitive operations：`purchase_tool`、`use_tool`、`spend_gold`、`start_game_session`、`complete_chapter`、`purchase`、`grant_membership`。
- risk score >=100 為 CRITICAL。
- CRITICAL 或 active restriction 時拒絕 sensitive operation。
- critical restriction 可由 server 施加，預設 24 小時，最大 30 天。

### Security Audit

`functions/security_audit.js`

目前 risk 規則：

- forged/reused transaction / authoritative data modification：100。
- illegal_gold：80。
- illegal_tool / invalid tool inventory / tool not allowed for chapter：50。
- abnormal frequency / repeated abnormal：20。
- mismatch / invalid wallet state：10。

累積 risk >=100 時會進入 critical restriction 流程；CRITICAL security event 亦會建立 admin notification。

## Game Session / Replay

- Session 由 server 建立並綁定 authenticated user。
- chapter、target、server start time、random session ID 均受 server authority 控制。
- 只有自己的 active session 可以完成章節。
- session 一次性完成。
- `completeChapter` 會執行 replay validation。
- Replay 為本機 event log + server deterministic replay validation，不需要每步 Firebase write。
- session start 與 final replay submission 使用 Firebase。
- Server 驗證包含初始棋盤、move、spawn、merge、score、chapter target、tool ownership/use、tool penalty、time rewind、final score/highest value、session ownership/expiration/one-time completion。
