## 帳號切換／本機存檔複查
- `PendingOperationStore` 的 operation ID 和 payload key 都包含 Firebase UID，因此待處理 RESET payload 有帳號分區。
- `SaveManager` 的主存檔 key 與全域 game session ID key 目前沒有 UID 命名空間；登出程式執行 Firebase signOut 前會清理部分 Life／Gold／Tool 記憶體狀態，但未明確切換本機快照與 session ID 的 UID 命名空間。
- 存檔與 Session ID 綁定有序列化佇列及 stale session ID 檢查，但這不等於完整的 UID 隔離。尤其不能只在登出時直接清空快照，因為這可能破壞同一帳號未完成棋盤；也不能清掉另一 UID 尚待重試的 RESET payload。
- 本輪未對 SaveManager 做冒險性改寫。下一步應採用明確 UID scoped snapshot/session key，定義登入狀態尚未恢復時的讀取行為，並測試 A 登出、B 登入、A 再登入及舊引擎延遲 autosave 的交錯情境。
