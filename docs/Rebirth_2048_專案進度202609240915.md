# 3. 本次已提交開發進展

## 3.1 本機優先進入遊戲

- [x] 新局進入時先在本機立即扣除 1 Life，不再等待 Firebase callable 完成才建立棋盤。
- [x] 已知本機 Life 為 0 時仍立即拒絕進入，避免明知無命仍建立遊戲。
- [x] Server `startGameSession` 改為背景驗證；成功後以 server-authoritative Life/session state 覆蓋本機 optimistic state。
- [x] 若 Firebase 回傳失敗，本機 Life 會重新向 server reconcile，而不是把 optimistic 扣命永久當成事實。
- [x] 若玩家在背景 session 尚未完成前就完成遊戲，completion 只在真正送出 completion 時等待 session verification，不拖慢一般棋盤操作。

## 3.2 Tool Inventory 不再阻塞遊戲建立

- [x] `ToolManager.refreshInventory()` 改為背景載入。
- [x] 建立棋盤不再等待 Tool Inventory callable。
- [x] Server inventory 回傳後仍會更新 authoritative tool cache。

## 3.3 後端仍維持權威驗證

- [x] `startGameSession` server transaction 仍實際執行 Life consume、chapter/session 驗證與 session 建立。
- [x] Firebase Functions region 維持 `us-central1`。
- [x] Security enforcement 仍在 sensitive operations 前檢查帳號 restriction/risk state。
- [x] Security audit 的 CRITICAL risk 累積到門檻時會套用 account lock；因此本機優先不是放棄後端防作弊，而是把網路等待從玩家操作路徑移到背景驗證。
