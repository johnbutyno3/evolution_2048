# Rebirth 2048 — 專案規則增補（Canonical Extension）

最後更新：2026-10-04（台灣時間）
基準：完整延續最新《Rebirth_2048_專案規則202609301400.md》全部有效內容；本檔只新增本次 Firebase/App Check 強化規則，不取代其他規則。

## 51. Firebase App Check 正式強制規則（ACTIVE）
1. Firebase App Check 是 Firebase 安全邊界之一，但不得取代 Firebase Authentication、Firestore Security Rules、Callable input validation、server authority、replay validation 或 risk/enforcement。
2. Cloud Functions v2 的重要 callable 必須啟用 App Check enforcement；不得只在 Flutter client 初始化 App Check 而由 server 不驗證。
3. Debug/Chrome 開發環境可使用 App Check Debug Provider；正式 Release 不得使用 Debug Provider。
4. Android Release 使用 Play Integrity；Apple Release 使用正式 Device Check/App Attest；Web Release 使用正式 reCAPTCHA v3/Enterprise provider。
5. Release Web 的 provider key 必須透過安全的 build-time configuration 提供，不得把 secret/debug token 寫入 source code。
6. Firebase App Check debug token 不得提交 Git，不得寫入正式 source code；若 token 外洩，應撤銷並重新建立。
7. 啟用 enforcement 前必須確認合法測試環境已註冊 App Check，避免把未註冊的正式 app 鎖在 Firebase 外。
8. App Check failure 必須被視為請求未通過 app/environment 身分驗證，不得 fallback 成成功。
9. App Check enforcement 不得改變 gameplay local-first 原則；普通移動仍不得變成 Firebase round-trip。
10. App Check 與 Auth 必須同時存在：合法帳號但非合法 app 不得取得受保護 callable；合法 app 但未登入也不得取得需要 Auth 的資源。

## 52. Firestore Feedback 完整性規則（ACTIVE）
1. 玩家只能建立自己的 Feedback。
2. 玩家建立後不得直接 update/delete 自己的 Feedback。
3. Admin 才能 read/update/delete Feedback。
4. Feedback 欄位與內容仍依既有正式規格，不得藉此自行增加未確認的產品欄位。
5. Feedback 是產品資料，不得成為 client 可任意修改的權威狀態。

## 53. Shop Config Authority 強化（ACTIVE）
1. shop_config/global 是商城價格與商品設定的 server-side source of truth。
2. Client 顯示價格可以使用快取，但購買與扣款永遠使用 server 重新讀取的 Shop Config。
3. Client 不得宣告購買成功或自行決定實際扣款價格。
4. 若 Shop Config 讀取失敗，server 不得用 client 提供的價格完成交易。
5. 程式中的 fallback 價格只能作為明確的非生產測試／bootstrap default；不得覆蓋有效 remote Shop Config，也不得讓 client 以 fallback 價格授權交易。
6. 後續應逐步收斂重複的 client/server 價格常數，避免價格漂移。

## 54. Firebase 修改驗證順序（ACTIVE）
Firebase 相關修改固定遵循：
最新規則 → 最新進度 → GitHub HEAD → source diff → tests → deploy → callable/runtime evidence → 更新進度

不得因 flutter analyze、npm test 或 deploy success 單獨宣稱 Firebase runtime 完成。
