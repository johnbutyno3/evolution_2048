## RESET 恢復流程補充

- RESET 啟動時先取得操作鎖，避免快速連點造成多個獨立請求。
- 有未解決的 pending RESET 時會阻擋新 RESET；生命不足時會釋放操作鎖。
- 若後端請求失敗，只有在重新讀取伺服器狀態成功、且 active session 仍是原 session 時，才清除 pending 記錄。伺服器狀態無法確認時保留 payload，避免遺失可能已提交的交易。
- 若恢復時確認後端未提交，會回到一般 session 路由，而不是一直停在恢復失敗狀態。
- 已更新契約測試，檢查 payload 先於後端請求保存及 pending RESET 的互斥。
