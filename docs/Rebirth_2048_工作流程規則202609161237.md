# Rebirth 2048 — 工作流程規則補充

版本：2026-09-16 12:37

## 1. GPT 自主作業原則

以 GPT 自己處理為原則，盡可能由 GPT 直接完成檢查、修改、建立文件、Git 作業與驗證。

## 2. Git 優先作業原則

所有可以由 GPT 透過 GitHub／Git 完成的工作，優先在 Git 專案處理，不先要求專案經理操作本機。

優先順序：

1. GPT 直接檢查目前 GitHub committed state。
2. GPT 能直接修改 GitHub 時，直接完成修改並提交。
3. 只有在 GPT 權限不足、工具無法執行，或必須依賴本機環境才能完成／驗證時，才要求專案經理執行 PowerShell 指令。
4. 專案經理執行後，GPT 負責後續讀取、檢查、驗證與整理。

## 3. 本機同步原則

本機不是第一作業位置。工作先以 Git 為主；一個工作段落完成並確認後，再要求／安排同步到本機。

本機同步後仍以 GitHub committed state 判定完成狀態。

## 4. 檔案庫暫時無法寫入時

GPT 檔案庫 `/2048/` 暫時無法建立檔案時，不得停工，也不得宣稱已完成檔案庫同步。

此時：

- 最新規則／進度先保存於 Git 專案 `docs/`。
- 檔名使用 YYYYMMDDHHMM 版本時間。
- 標記為待同步至 GPT 檔案庫。
- 檔案庫恢復寫入能力後，再將最新版本新增至 `/2048/`。

## 5. 規則／進度版本判定

新對話開始時，同時檢查：

- GPT 檔案庫 `/2048/`
- Git 專案 `docs/`

兩邊若存在日期時間版本檔，**一律以日期時間最新的檔案為準，不因儲存位置不同而優先使用舊版本。**

若最新版本位於 Git `docs/`，而 GPT 檔案庫暫時無法寫入，Git 版本即為目前工作基準，直到檔案庫恢復並完成同步。

## 6. 新對話啟動

1. 比對 GPT `/2048/` 與 Git `docs/` 的最新日期時間版本。
2. 以最新版本作為 Source of Truth。
3. 讀取最新專案規則。
4. 讀取最新專案進度。
5. 檢查 GitHub 最新 committed state。
6. 確認目前未完成工作。
7. 直接繼續下一項，不要求專案經理重新說明已完成內容。
