## 2. 發現的根本問題

### 2.1 Firebase Functions 存在「多份同名實作」風險

`functions/package.json` 的 `main` 是 `bootstrap.js`。

`bootstrap.js` 原本依序載入：
1. `index.js`
2. `game_session.js`
3. `life.js`
4. `tool_inventory_defaults.js`
5. `admin_test.js`

因此同名 callable 若同時存在於 `index.js` 與後載入模組，後載入模組會覆蓋前一份 export。這正是「Git 看起來已修好，但實際部署功能又是另一份」的高風險來源。

本次確認：
- `getToolInventory` / `purchaseTool` / `useTool` 同時存在於 `index.js` 與 `tool_inventory_defaults.js`。
- `restartGameSession` / `abandonGameSession` 同時存在於 `index.js` 與 `game_session.js`。
- `life.js` 與 `index.js` 也有生命相關 helper／callable 的分層重複風險。

### 2.2 Tool Test Mode 曾只修到 index.js，實際 bootstrap 會使用另一份

`tool_inventory_defaults.js` 原本沒有：
- `allToolsEnabledForTest` 回傳。
- Test Mode 下允許所有工具的 `useTool` 邏輯。

因此先前 Git 的修正並不等於實際執行的 callable 已修正。

### 2.3 Replay Validator 曾沒有跟 Tool Test Mode 同步

即使 client 與 server `useTool` 允許 Test Mode 使用全部四種工具，`completeChapter` 的 replay validation 仍固定採正常章節工具白名單。

因此 Test Mode 使用 C1/C2/C3 中額外工具後，完成章節可能被 replay validator 拒絕。
