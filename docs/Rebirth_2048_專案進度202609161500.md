## 本工作單位：Security Enforcement Layer
Commit: `628b847e77cdcaa25c6826452530b10dfaf3a1f7`

新增：`functions/security_enforcement.js`

用途：建立單一 server-side sensitive-operation enforcement layer，避免未來在各 callable 中建立多套風險封鎖邏輯。

目前支援的敏感操作識別：
- purchase_tool
- use_tool
- spend_gold
- start_game_session
- complete_chapter
- purchase
- grant_membership

目前規則：
- NORMAL：允許
- WARNING：允許
- ADMIN_ALERT：允許，但持續由 Security Audit / Admin Notification 監控
- CRITICAL：敏感操作拒絕
- 已存在有效 restriction：敏感操作拒絕

限制狀態由 server-only `security_enforcement/{uid}` 管理；client 不應直接寫入。
`applyCriticalRestriction()` 預設限制 24 小時，最長 30 天。

### 重要狀態
本工作單位目前只建立 Enforcement Layer，**尚未把所有敏感 callable 接入 Gate**。
原因是必須先確認 Firestore rules 與 security_audit 的 CRITICAL 事件觸發點，再逐一接入，避免出現「有 Gate 但沒有產生 restriction」或繞過 Gate 的半套安全系統。
