# 20. 文件管理與恢復規則

規則或進度有變更時，檔案庫因無法覆蓋既有檔案，必須建立新的規則檔及進度檔。檔名格式：

- `Rebirth_2048_專案規則○○○○.md`
- `Rebirth_2048_專案進度○○○○.md`
- `○○○○` 為建立檔案時的日期及時間（YYYYMMDDHHMM）。

新檔建立後，以最新日期時間檔案作為目前有效版本；不得因檔案庫存在舊版本而恢復舊規則或舊進度。

未來只保留兩份 canonical 文件：

1. **《Rebirth 2048 — 專案規則》**：唯一規則來源，不記錄每日進度。
2. **《Rebirth 2048 — 專案進度》**：唯一進度來源，記錄 committed state、完成／未完成項目、測試結果、階段與下一步。

任何新的開發對話開始：
1. 先讀最新《專案規則》。
2. 再讀最新《專案進度》。
3. 檢查 GitHub `feature/chapter1-spec-implementation` 最新 commit。
4. 檢查目前實際程式碼。
5. 規則以《專案規則》為準。

### B. 新增 `resumeGameSession`

`functions/index.js` 已新增 `resumeGameSession`：

- 驗證 authenticated user。
- 驗證 chapter index。
- 驗證目前存在 matching active game session。
- 驗證 session 尚未失效。
- 在同一 Firestore transaction 中執行 Life consumption。
- 保留原本 active session ID，不建立另一個棋盤 session。
- 回傳原 active session ID 與 chapter index。

因此「恢復原本未完成盤面」與「進入遊戲扣 1 Life」現在可以同時成立。

### C. Flutter active-session entry 改走 `resumeGameSession`

`Evolution2048Page._ensureGameSession()` 現在：

- 沒有 active session → `startGameSession()` → 新局扣 1 Life。
- 有同章 active session → `resumeGameSession()` → 原局恢復且扣 1 Life。
- Restart → `restartGameSession()` → 新局扣 1 Life。
- Game Over → `abandonGameSession()` → 不退款；再次進入 → `startGameSession()` → 新局扣 1 Life。

這與 Canonical Rules §8.1 A～F 對齊。
