# Rebirth 2048 專案進度 — 2026-10-20 13:00

## RESET 結果不明時不得回滾舊棋盤

本輪沿著 RESET 失敗分支追查到更重要的競態：`restartGameSession` 回傳 `false` 不一定代表後端已確認沒有提交。服務層可能因網路／執行期錯誤保留 pending payload；畫面原本卻仍可能把它當成確定拒絕，回寫舊棋盤，和後端實際已提交的新 session 不一致。

已修正：

- RESET 回傳 false 後，先檢查該帳號是否仍有未解決的 RESET payload。
- payload 仍存在時，不再回寫舊棋盤、不清除待恢復資料；停止新棋盤計時並鎖住棋盤操作，提示使用者離開後重新進入該章以重試相同 operation ID。
- 只有服務層已權威確認未提交並清除 pending payload，才走舊棋盤回滾路徑。
- 加入契約測試，檢查回滾前必須先查 pending 狀態，且未解決 RESET 時工具操作保持鎖定。
