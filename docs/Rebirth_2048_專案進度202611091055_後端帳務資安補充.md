# Rebirth 2048 專案進度補充 — Supabase 帳務與資安審核

接續 `Rebirth_2048_專案進度202611091055_驗收補充.md`。

## 本次新增檢查與修正

### 1. 工具購買交易
- 核對 `purchase_tool_package`：價格由 server-side `shop_config` 取得，忽略客戶端價格。
- 同一 idempotency key 會核對 Gold／Tool 兩筆 wallet ledger；缺少其中一筆或 payload 不符即拒絕。
- 會員資格、FREE 單個購買限制、GOLDEN 不出售 UNDO、Gold 餘額與工具庫存均在同一資料庫交易內核對／更新。
- Gold wallet 與 tool inventory 使用 row lock；Gold 扣除、工具增加及兩筆 ledger 寫入同一交易完成。
- 新增 `supabase/tests/tool_purchase_contract.test.js`，納入 CI 的全部 Supabase Node contract tests。

### 2. 工具使用結算
- 核對 `abandon_game_session`：依 replay toolUsage 與已結算 usage 計算差額，透過 wallet ledger 扣除工具；同一 eventId 重送不重複扣除。
- 放棄或 Game Over 不退還已扣除 Life。
- Restart 透過同一資料庫交易先結算舊局，再建立 replacement session；不再次扣 Life。
- 新增 `supabase/tests/session_settlement_contract.test.js`。

### 3. 可疑事件與帳號鎖定
- 原本 finish／abandon／restart Edge Functions 會把部分工具結算差異回報為 ACCOUNT_RESTRICTED；過關 replay validation failure 還會直接呼叫鎖帳 RPC。
- 已改為將 replay validation failure 與工具結算差異寫入 `security_events`，使用 eventId＋reason 去重；該筆結算拒絕並回報可聯絡客服，不會單憑一次異常直接鎖定帳號。
- 新增共用 helper：`supabase/functions/_shared/security_events.ts`。
- 新增 migration：`20261109120000_security_event_idempotency.sql`。
- 鎖帳 RPC 仍保留 service-role-only 權限，供確認違規後的管理處理；正式管理者審核／鎖帳 UI 尚未完成。
- 新增 `supabase/tests/security_review_contract.test.js`。

### 4. CI
- `.github/workflows/supabase-audit.yml` 現在執行 `node --test supabase/tests/*.test.js`，涵蓋 Restart、存檔復原、工具購買、Session 結算與資安審核合約。
- Deno type-check 步驟會透過 finish／abandon／restart Edge Functions 一併檢查 security event helper。
