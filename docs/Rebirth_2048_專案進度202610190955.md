## 已確認的問題與本次變更

### 1. 返回首頁後遊戲時間倒退

`Evolution2048Page._handleSystemBack()` 原先先建立 `saveData`，再呼叫 `pauseGameTimer()`。計時器暫停會累加已經過秒數並排入新存檔，但隨後保存較早建立的 `saveData`，可能覆蓋更新的計時資料。

修正：先暫停計時器，再建立要保存的快照。

### 2. 生命未扣除的競態風險

`PlayerProgressService.startGameSession()` 在已有 `_pendingStartSession` 時，原先直接回傳 `true`。呼叫端可能把另一個本機新棋盤誤當成既有待處理伺服器工作所擁有的棋盤，並將它與既有 Session 綁定，造成未建立新 Session／未扣新生命卻顯示新棋盤的競態。

修正：一般重複呼叫遇到待處理 Session 時回傳 `false`，不把另一個棋盤當作已成功建立；完成章節後明確要求重試的流程仍會等待原始請求結果。

此為依程式路徑確認的競態修正，仍需本機測試確認實際生命顯示與伺服器帳面一致。

### 3. 重置後舊棋盤復原

已確認畫面在 `restartGameSession` 回傳失敗或發生例外時，會復原舊棋盤。這是目前的失敗回復設計；尚未取得實際執行時的根本錯誤，因此不能宣稱重置問題已完全修好。

本次新增：
- `PlayerProgressService.restartGameSession()` 印出非 `FirebaseFunctionsException` 的例外與堆疊。
- 重置流程的例外回復處理印出錯誤與堆疊。

目的是在下一次執行時取得確切失敗原因，再針對真正的後端／資料驗證問題修正，而不是略過伺服器驗證或盲目保留未綁定的新棋盤。
