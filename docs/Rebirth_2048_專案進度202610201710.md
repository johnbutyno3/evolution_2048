## 已完成：本機帳號資料隔離

### SaveManager

- 遊戲存檔與 Game Session ID 改用 UID 專屬的 SharedPreferences key。
- 玩家名稱、玩家 ID、頭像索引快取也改為 UID 專屬 key；延遲寫入在帳號已切換時會被拒絕。
- `bindAccount(uid)` 在進入首頁前載入該 UID 的存檔命名空間；登入流程也會先綁定 UID。
- 登出流程在 Firebase Auth signOut 後解除原帳號的本機存檔綁定。
- GameEngine 建立時捕獲 `saveOwnerUid`；SaveManager 只接受與目前帳號相符的快照。
- ReplayRecorder 使用建立時捕獲的 UID，避免舊引擎的回放記錄被寫入其他帳號。
- 非同步設定 Session ID 可傳入 `expectedUid`；過期帳號的回應不能替目前帳號綁定 Session。
- PlayerProgressService 的 start/resume/restart/refresh 路徑增加帳號 UID 檢查，防止舊帳號網路回應提交至目前本機狀態。

### 舊版存檔安全遷移

舊版全域存檔與 Session key 不會直接刪除，也不會任意歸給目前登入者。只有同時符合以下條件才會遷移：

1. 使用者已登入且已綁定 UID 專屬存檔空間。
2. 舊版 Session ID 與伺服器回傳的權威 active Session ID 完全相同。
3. 指定章節的快照 Session ID 也相同，棋盤為 16 格且尚未結束。
4. 遷移執行期間帳號及 Session 的所有權仍有效。

遷移只複製與該 active Session 相符的章節；舊版全域資料保留不動。若無法證明所有權，則不遷移。

### 舊 Session 棋盤恢復防護

- `SaveManager.loadCached` 現在檢查快照的 Session ID 是否與目前綁定 ID 相符。
- 舊 Session 的快照不會被當成當前可恢復棋盤。
- RESET/存檔競態測試更新為先寫入當前 Session 的有效快照，再確認舊 Session 的延遲快照無法取代它。
