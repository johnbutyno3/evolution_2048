## 1. 專案定位

Rebirth 2048 是使用 Flutter 建構的 4×4 生物演化／生態系統復興遊戲。

核心概念：

- 玩家扮演人工智慧，模擬地球過去、現在及未來的生命與文明演化。
- 棋盤採用 2048 式移動與合併機制。
- 生物／物件影像是主要圖塊視覺元素。
- 數值為遊戲內部數值。
- 遊戲共有六個權威章節。
- 本地資料只用於遊戲狀態恢復。
- Gold、Membership、Tool Inventory、Purchase、Game Session、Chapter progression、Security Event 等受保護資料由伺服器權威控制。
- Chrome 是目前桌面實際測試目標。

技術基礎：Flutter 3.44.6、Dart 3.12.2、Firebase、Firestore、Firebase Authentication、Cloud Functions。

## 2. 絕對開發規則

### 2.1 專案經理工作量最小化

1. 盡量由 GPT 直接檢查、修改、建立文件、Git 作業與驗證。
2. 需要專案經理執行時，必須提供完整可直接執行指令，不得要求自行查找。
3. 預估需要開新對話時，先更新規則與進度並準備銜接指令。
4. 規則或進度有變更時，建立新的時間戳檔，不覆蓋舊檔。

### 2.2 Git-first

- 可以由 GPT 透過 GitHub／Git 完成的工作，優先直接在 Git 處理。
- 只有權限不足、工具無法執行或必須依賴本機環境驗證時，才要求 PowerShell。
- 工作段落完成並確認後再同步本機。
- 以 GitHub committed state 判定完成狀態；本機未提交修改不得視為完成。

### 2.3 禁止事項

1. 不得恢復舊版 18 階 creature data。
2. 不得恢復衝突舊 l10n 或 backup。
3. 不得建立第二套互相競爭的遊戲／工具規則配置。
4. 不得把本機資料視為 authoritative data。
5. 不得為每一步普通遊戲移動建立 Firebase 寫入。
6. 除非明確要求，不啟動真正 Google Play／Apple 付款驗證。
7. 不得以截斷內容覆蓋大型來源檔案。
8. 修改程式碼前先檢查實際目前版本。
9. 實際驗證前不得標示完成。
10. Flutter 提交前必須 `flutter analyze` 且 `No issues found!`。
11. 提交前必須 `git diff --check`。
12. 不 force push。
13. 保留無關既有修改。
14. 每次只處理一個明確任務，除非明確要求連續處理。
15. 不為配合舊程式碼改變既定規則。
16. 國際版所有付費金額使用 USD。
17. 國際版目前維護 English / Traditional Chinese。
18. 非核心功能不得擅自改變核心規則或阻塞核心開發。
19. **不得提供會關閉、終止、殺掉或重啟目前 PowerShell／Terminal 工作階段的指令。**
20. **不得使用或建議 `exit`、`Stop-Process`、`taskkill` 或任何等效終止目前終端機工作階段的方式。**
21. **本機檢查失敗時，只能輸出錯誤／警告並保留目前 PowerShell／Terminal 工作階段，不得以關閉終端機作為錯誤處理方式。**
22. **所有提供給專案經理執行的 PowerShell 指令，必須以不關閉目前終端機工作階段為前提。**

## 5. 工具庫存

- 永久、持續、累積。
- 使用有限工具後 -1。
- 未使用工具進下一章全部保留。
- 商店購買直接加入庫存。
- 章節獎勵只增加指定工具，不重設舊庫存。
- C6 即使不能使用部分工具，庫存仍永久保留。
- 工具庫存與目前章節使用權限分離。

工具：UNDO、REMOVE、SWAP、DUPLICATE。

## 6. 工具使用與 UNDO

- 有限工具為 0 時不得執行，直接開對應工具購買頁；UNDO 可依會員與本局限制提供 Rewarded Ad。
- GOLDEN 的 UNDO 為 ∞，不得購買有限 UNDO，也不消耗有限 UNDO。
- UNDO 不可連續使用；GOLDEN 同樣遵守鎖定規則。
- Rewarded Ad 每局最多取得 2 次 UNDO。
- REMOVE／SWAP／DUPLICATE 不得透過廣告取得。
- 工具選擇音效固定 `tool_select.mp3`。

## 7. 計分

- 合成產生新階級時取得該新階級分數。
- 工具使用扣分：UNDO 扣上一步所得分數；REMOVE 扣被移除項目階數／數值；SWAP 扣兩 Tile 階數／數值總和；DUPLICATE 扣被複製項目的分數／數值。
- 最低 0，不顯示負分。
- 排行榜以每章最終分數與最高階為成績資訊；同分同階以過關時間較短者優先。

## 8. Life

- FREE：上限 5，每 60 分鐘 +1。
- PREMIUM：上限 5，每 30 分鐘 +1。
- GOLDEN：∞，不消耗。
- Life 不作獨立商城商品。
- Game Over、Restart、異常退出、章節完成依鐵律處理。
- 不正常結束或過關接續流程：生命先返還，再依重新進入規則扣除；Game Over 不返還；Game Over 後新遊戲扣 1 Life。

## 9. Game Over

- 4×4 已滿、無相鄰可合成、尚未達章節目標時 Game Over。
- 有 Life 時正常 Restart 扣 1。
- Life > 0 不提供 Rewarded Ad 復活。
- Life = 0 可一次 Rewarded Ad 復活，同一 Game Over 不可重複。

## 10. Rewarded Ads

- 必須玩家主動選擇，完成觀看才發獎。
- 不得因 callback 重複發獎。
- FREE 每累積遊戲 30 分鐘主動播放時間廣告；PREMIUM／GOLDEN 不播放。
- UNDO 廣告每局最多 2 次；新局重新計算。

## 11. Membership

- FREE：免費。
- PREMIUM：USD 2.99/月，No Ads、Life 30 分鐘 +1。
- GOLDEN：USD 5.99/月，No Ads、Infinite Lives、UNDO ∞。
- Membership 不改變核心 2048 規則。
- Membership 狀態由 server authority 解析。

## 20. Firebase / Authentication

- Project：`rebirth-2048`。
- Firestore：`nam5 (United States)`。
- Google、Apple、Email/Password 啟用；電話驗證暫不開放。

## 21. Server Authority

必須 server-authoritative：Gold、Membership、Tool inventory、Tool spending、Golden Infinite Lives、Purchases、Chapter progression、Game sessions、Security events。

主要 callable：`getGoldBalance`、`spendGold`、`getMembershipStatus`、`grantMembership`（Admin only）、`getToolInventory`、`purchaseTool`、`useTool`、`createPurchaseIntent`、`submitPurchaseForVerification`、`startGameSession`、`completeChapter`。

Firestore production client write 必須嚴格限制；Client UI、SharedPreferences、本機 save、APK／Flutter 修改均不能取得 protected resource authority。

## 22. 購買安全

商品／價格由 server / remote Shop Config 驗證；Client 不得 grant Gold 或 Membership；transaction 唯一且 idempotent；爭議以可驗證憑證為準；正式 Google Play / Apple receipt verification 暫緩；production 不得 fake purchase success。

## 23. Game Session / Replay / Anti-Cheat

Session 必須由驗證 server 建立並綁定 authenticated user；記錄 chapter、target、server start time、random session ID；只能由自己的 active session 完成，每 session 一次，chapter index 0..5，target 必須符合章節設定；malformed / impossible replay 必須拒絕並可記錄 security event。

Replay 採本機 event log + server deterministic replay validation；不需每步 Firebase，僅 session start 與 final replay submission 使用 Firebase。Server 必須驗證初始棋盤、move、spawn、merge、score、chapter target、tool ownership/use、tool penalty、time rewind、final score/highest value、session ownership/expiration/one-time completion。未完成整合與驗證前不得宣稱完整 anti-cheat 完成。

## 24. Security Audit

Server 產生安全事件，可含 eventId、uid、playerId、eventType、severity、reason、clientValue、serverValue、productId、toolType、transactionId、requestId、platform、appVersion、timestamp、status。

Severity：WARNING、SUSPICIOUS、CONFIRMED、CRITICAL。Risk：Data mismatch +10、Abnormal frequency +20、Illegal tool +50、Illegal Gold +80、Forged transaction +100；0–29 Normal、30–59 Warning、60–99 Admin Alert、100+ Critical。Client 不得建立／修改／刪除 audit record 或 risk score。單一 suspicious event 不自動等同封號。

## 25. Firestore 安全

Client 不得直接修改 Gold、Membership、Tool inventory、Purchase status/amount/product、verification state、transaction uniqueness、security audit、risk score、Chapter progression。`users/{uid}` authoritative fields 必須明確保護；wallet 等敏感資料不得 client write；game_sessions 不可任意存取；`security_events` server-only write / admin-read。

## 26. 本地保存

本地 save 只用於恢復：棋盤、分數、章節／階段、恢復工具及相關遊戲狀態；Replay integration 後保存 replay data。Protected authoritative data 不得依賴 local save。

## 27. 付款整合界線

## 31. GPT 自主作業與 Git-first 工作流程

### 31.1 GPT 自主作業原則

以 GPT 自己處理為原則，盡可能由 GPT 直接完成檢查、修改、建立文件、Git 作業與驗證。

### 31.2 Git 優先作業原則

所有可以由 GPT 透過 GitHub／Git 完成的工作，優先在 Git 專案處理，不先要求專案經理操作本機。

優先順序：

1. GPT 直接檢查目前 GitHub committed state。
2. GPT 能直接修改 GitHub 時，直接完成修改並提交。
3. 只有在 GPT 權限不足、工具無法執行，或必須依賴本機環境才能完成／驗證時，才要求專案經理執行 PowerShell 指令。
4. 專案經理執行後，GPT 負責後續讀取、檢查、驗證與整理。

### 31.3 本機同步原則

本機不是第一作業位置。工作先以 Git 為主；一個工作段落完成並確認後，再要求／安排同步到本機。

本機同步後仍以 GitHub committed state 判定完成狀態。

## 32. 檔案庫暫時無法寫入時

GPT 檔案庫 `/2048/` 暫時無法建立檔案時，不得停工，也不得宣稱已完成檔案庫同步。

此時：

- 最新規則／進度先保存於 Git 專案 `docs/`。
- 檔名使用 `YYYYMMDDHHMM` 版本時間。
- 標記為待同步至 GPT 檔案庫。
- 檔案庫恢復寫入能力後，再將最新版本新增至 `/2048/`。

**重要：Git fallback 文件必須延續 File Library 最新完整版本，不得改成短摘要或只保存增量片段。**

## 33. 規則／進度版本判定

新對話開始時，同時檢查：

- GPT 檔案庫 `/2048/`
- Git 專案 `docs/`

兩邊若存在日期時間版本檔，**一律以日期時間最新的檔案為準，不因儲存位置不同而優先使用舊版本。**

若最新版本位於 Git `docs/`，而 GPT 檔案庫暫時無法寫入，Git 版本即為目前工作基準，直到檔案庫恢復並完成同步。

## 34. 新對話啟動

1. 比對 GPT `/2048/` 與 Git `docs/` 的最新日期時間版本。
2. 以最新版本作為 Source of Truth。
3. 讀取最新專案規則。
4. 讀取最新專案進度。
5. 檢查 GitHub 最新 committed state。
6. 確認目前未完成工作。
7. 直接繼續下一項，不要求專案經理重新說明已完成內容。

## 35. 規則／進度版本保存

- 每次規則／進度更新都建立新的日期時間檔，不覆蓋舊檔。
- 最新時間戳版本才是該類型文件的有效版本。
- 若 File Library 與 Git 都可寫，完成工作段落後應使兩邊最終可同步到同一最新版本。
- 若 File Library 暫時不可寫，Git `docs/` 保存完整最新版本，並標示待同步。
- 不得要求專案經理手動搬移文件，除非 GPT 確實沒有任何可用的檔案操作權限。

- 只輸出失敗原因與下一步處理方式。
- 不得用關閉終端機方式處理錯誤。
- 不得要求專案經理重新開一個終端機作為一般錯誤處理手段。

### 37.4 PowerShell 指令安全要求

未來提供 PowerShell 指令時，必須以「執行完成後仍留在目前 PowerShell 工作階段」為基本要求。若某項操作可能改變或終止目前工作階段，GPT 必須改用不影響工作階段的安全寫法。

### 37.5 本規則與既有 Git-first 規則同時適用

優先由 GPT 直接在 GitHub／Git 完成工作；只有確實需要本機操作時才提供 PowerShell。即使必須使用 PowerShell，也不得以任何方式關閉目前終端機工作階段。
